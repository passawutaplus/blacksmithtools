## สรุปผู้บริหาร

โครงตอนนี้ดีกว่าเครื่องคิดเลขออนไลน์ทั่วไปมาก — มี **13 สายงาน · 72 เครื่องมือ · 13 หน้า “คิดทั้งงาน”** ค่าคงที่รวมศูนย์พร้อมแหล่งอ้างอิง กางสูตรได้ จัดชั้นความเสี่ยง A/B/C กราฟประกอบผล และออกแบบมือถือมาแล้ว (แถบคำตอบล่างจอ + ผลติดข้างบนเดสก์ท็อป)

สิ่งที่ยังห้ามวางใจใช้หน้างานมี 3 กลุ่ม:

1. **ตัวเลขผิดจริง** — ตาราง P–T น้ำยาแอร์คลาดประมาณ 20 °C (ค่าตั้งต้นของ SH/SC วินิจฉัยว่าน้ำยาเกิน ทั้งที่ระบบปกติ), ทับหลังคูณเหล็กเกิน ~3 เท่า, ท่อ PVC เทียบ ID กับขนาดเรียก, สายไฟเกินตารางแล้วยังตอบเหมือนผ่าน
2. **อินพุตว่าง/ติดลบไหลทะลุ** — ล้างช่องเพื่อพิมพ์ใหม่ได้ผลเป็น 0 แล้วบางสูตรตอบ `∞`; ค่าติดลบได้ “ปูน −4 ถุง”
3. **คำเตือนชั้น C ไม่ติดไปกับของที่ส่งลูกค้า** — คัดลอก / แชร์ / บันทึกรูปไม่มี `DISCLAIMER_C` และสูตรอยู่ล่างสุดของหน้า

เทส `npm test` ผ่าน 40/40 แต่จับปัญหาข้างบนไม่ได้ เพราะตรวจแค่ค่าตั้งต้นรันได้และไม่มีคำว่า `NaN` (ส่วน `∞` ผ่านฉลุย)

**หมายเหตุธุรกิจ:** ร้านนี้ไม่ได้ขายวัสดุก่อสร้าง (ปูน/กระเบื้อง/สายไฟ) — catalog ประมาณ 161 SKU เป็นที่เก็บเครื่องมือ / ที่เก็บแบต / กล่อง / เจลล้างมือ — ห้ามทำ “คำนวณเสร็จใส่ตะกร้า” ตรง ๆ

ด้านล่างเป็นลิสต์ติ๊กได้ เรียงตามความสำคัญ

## ส่วนที่ 1 — สูตรและมาตรฐานที่ต้องแก้

ติ๊กเมื่อแก้แล้ว · ไฟล์อ้างอิงเป็น absolute path ภายใต้ `src/lib/chang/tools/`

### 🔴 Critical — ผลลัพธ์ผิดหรืออันตราย

- [ ] **ตาราง P–T น้ำยาแอร์คลาด ~20 °C — ยืนยันด้วยค่าตั้งต้นจริง**  
  `hvac.ts` → `satTemp`  
  จุด `[100, 20]` / `[150, 33]` ของ R32 ไม่ตรงตารางอิ่มตัว (R32 ที่ ~100 psig ใกล้ 0 °C ไม่ใช่ 20 °C) · R22 ช่วงใช้งานดูเหมือนคัดลอกมาจาก R134a  
  เปิด `assistant/hvac/shsc` ด้วยค่าตั้งต้น (R32, ดูด 120 psi / 12 °C, ของเหลว 380 psi / 38 °C) ได้ Superheat **−13.2 °C** แล้วสรุปว่า “น้ำยาเกิน” ทั้งที่ค่าถูกประมาณ SH ≈ 9.5 °C / SC ≈ 6 °C = ปกติ  
  **แก้:** ใส่ตาราง P–T จาก TDS / REFPROP หน่วย psig ให้ชัด ล็อกด้วย golden test ที่ 100 / 150 / 200 psi อย่างน้อย 3 จุดต่อน้ำยา

- [ ] **ล้างช่อง / ใส่ 0 แล้วได้ `∞` หรือ NaN**  
  `math.ts` → `num()` แปลง `""` เป็น 0; `fmt(Infinity)` ได้ `"∞"` ซึ่งเทสห้ามแค่คำว่า `NaN`  
  พบอย่างน้อย 14 เครื่องมือ เช่น `electrical/solar` (sun/panel=0), `electrical/battery` (DoD/eff=0), `steel/deflection` (I=0), `glass/sealant` (gap/depth=0), `handyman/stair` (r=0)  
  **แก้:** ช่องว่างไม่คำนวณ · ตัวหารต้อง > 0 · ถ้าอินพุตไม่ครบให้ข้อความ “กรอกช่องนี้ก่อน” ไม่ใช่เลขเพี้ยน

- [ ] **ค่าติดลบไหลทะลุทุกสูตร**  
  `Fields.tsx` ส่ง `min` เป็นแค่ HTML attribute; `CalcScreen` เรียก `calc(values)` ตรง ๆ  
  ได้ผลเช่น “แผ่นยิปซัม −1 แผ่น”, “ปูนซีเมนต์ −4 ถุง”, “ลูกนอน −237 ซม.” · บางช่องไม่มี `min` เลย (เช่น `hvac/shsc.sucT`, `electrical/string.voc`)  
  **แก้:** ชั้น validate กลางก่อนคำนวณ ห้ามติดลบในปริมาณวัสดุ / ความยาว / กระแส

- [ ] **เลือกขนาดสายไฟเกินตารางแล้วยังตอบเหมือนผ่าน**  
  `electrical.ts` → `pickCable` / `pickBreaker`  
  โหลดเกินแถวสุดท้าย (95 ตร.มม. / เบรกเกอร์ 250 A) แล้ว fallback ค่าสุดท้ายแบบเงียบ  
  **แก้:** ขึ้นสถานะ “เกินช่วงออกแบบ ต้องให้วิศวกรไฟฟ้า” ห้าม headline แบบสำเร็จ

- [ ] **ขนาดท่อ PVC เทียบเส้นผ่านศูนย์กลางคำนวณกับขนาดระบุ**  
  `plumbing.ts` → `calcPlumbPipe`  
  30 ล./นาที ที่ 1.8 ม./วินาที ได้ d ≈ 18.8 มม. → แนะนำท่อ 20 มม. แต่ ID จริงของ PVC ชั้น 13.5 ขนาด 20 มม. อยู่ราว 16 มม. ความเร็วจริงพุ่งเกิน 2.4 ม./วินาที  
  **แก้:** ตาราง OD → ID ตามชั้นคุณภาพ (8.5 / 13.5) แล้วเลือกจาก ID

- [ ] **เหล็กทับหลังคูณเกิน ~3 เท่า**  
  `masonry.ts` → `calcLintel`  
  สูตร `n * (4*len + 8*(len/0.15)*0.35)` — ตัวคูณ 8 ที่ปลอกไม่สมเหตุสมผล  
  ช่องเปิด 1 ม. × 2 ชุดได้เหล็ก RB6 ราว 60+ ม. ทั้งที่เหล็กยืน 4 เส้น + ปลอกทุก 15 ซม. ควรราว 20 ม.  
  ชื่อเครื่องมือมี “เสาเอ็น” แต่คิดแค่ทับหลัง  
  **แก้:** จำนวนปลอก ≈ ยาว/0.15 แล้วคูณเส้นรอบหน้าตัด 10×10 + ตะขอ ไม่ใช่ ×8 · แยกเครื่องมือเสาเอ็น

### 🟠 High — ไม่ตรงมาตรฐาน หรือทำให้เข้าใจว่าใช้ติดตั้งได้เลย

- [ ] **BTU นับความร้อนซ้ำได้**  
  `hvac.ts` → `calcBtu`  
  ประเภทห้อง `hot` รวมครัว / ทิศตะวันตก / ชั้นบนสุด ไว้แล้ว ฟอร์มยังมีแดดบ่าย (+15%) และติ๊กชั้นบนสุด (+10%) อีก  
  ขัดหลักการในเอกสารสูตรข้อ “ห้ามนับความร้อนจากแดดซ้ำสองรอบ”  
  **แก้:** ถ้าเลือก `hot` ให้ปิดหรือรวมตัวคูณแดด-ชั้นบน และเตือนว่านับไปแล้ว

- [ ] **ปริมาณลวดเชื่อม ชนิดแนวไม่ต่างกัน**  
  `steel.ts` → `calcWeld`  
  `fillet` / `v` / `sq` ใช้หน้าตัด `0.5 × z²` ตัวเดียวกัน  
  **แก้:** fillet ≈ ½z², V-groove ตามมุม/หน้าแยก, square ตามช่องว่าง × หนา + golden test ต่อชนิด

- [ ] **`DISCLAIMER_C` ไม่ติดไปกับคัดลอก / แชร์ / บันทึกรูป**  
  แสดงแค่ใน `FormulaNote` (ล่างสุดของหน้า ใต้ฟอร์ม) และปุ่ม “คัดลอกพร้อมสูตร”  
  `makeCopy` ต่อท้ายแค่ “ค่าประมาณหน้างาน” · `downloadResultPng` วาด title/headline/rows/tip อย่างเดียว — รูปนี้คือสิ่งที่ส่งลูกค้า  
  ขัดหลักการที่ชั้น C ต้องบังคับแสดง ห้ามหุบ  
  **แก้:** งานชั้น C ใส่คำเตือนในการ์ดผล + ข้อความคัดลอก + PNG เสมอ และย้ายป้ายความเสี่ยงขึ้นเหนือ headline

- [ ] **หน้าคิดทั้งงานแอร์ / ก่อฉาบ คำเตือนชั้น C หล่น**  
  `hvac.ts` → `hvacJob` รวมเบรกเกอร์+สาย แต่ `explain.risk` ยังเป็นชั้น B ของ BTU  
  `masonry.ts` → `masonryJob` รวมทับหลังชั้น C แต่ส่ง explain จากสูตรอิฐชั้น A  
  **แก้:** รวม disclaimer ชั้น C ให้เห็นตลอด ไม่หุบในสูตรอย่างเดียว

- [ ] **บันไดไม่เทียบกฎกระทรวง (T1)**  
  `handyman.ts` → `calcStair`  
  ใช้ Blondel `2R+T ≈ 63` ซึ่งเป็นแนวปฏิบัติ ไม่เช็กความกว้างขั้น, จำนวนลูกนอน = n−1, ราวกันตก  
  เกณฑ์ในโค้ด (R 15–19, T 22–30) ใกล้เคียงแต่ไม่ได้อ้างกฎหมาย  
  **แก้:** เทียบกฎกระทรวงควบคุมอาคาร แล้วบอกชัดว่าสูตรก้าวเดิน ≠ แบบก่อสร้าง

- [ ] **พุกไม่ดูน้ำหนักเมื่อไม่ใช่คอนกรีต**  
  `handyman.ts` → `calcScrew`  
  อิฐ / ยิปซัม / ไม้ไม่ใช้ค่าน้ำหนักที่กรอก — แขวน 50 กก. บนยิปซัมยังได้พุกปีกผีเสื้อ  
  **แก้:** ของแขวนหนักเป็นชั้น C · บังคับจำนวนจุดยึด · ปฏิเสธยิปซัมแผ่นเดียวเมื่อเกินพิกัด

- [ ] **ความชันหลังคาเป็น % แต่ช่างไทยพูดองศา**  
  `roof.ts` ช่อง `pitch` unit `%` default 30  
  ถ้าใส่ 30 นึกว่า 30° พื้นที่จริงจะขาดประมาณ 10% (30% ≈ 17°)  
  **แก้:** สลับหน่วย % / องศา และโชว์เทียบ “30% ≈ 17°”

- [ ] **ตัดอลูมิเนียมหักเฟรมไม่สมมาตร**  
  `glass.ts` → `calcAluCut`  
  กว้างหักหน้าตัดเฟรมครั้งเดียว สูงไม่หัก — ไม่ใช่ทั้งมุม 45° (ใช้ขนาดนอกทั้งสี่ด้าน) และไม่ใช่ชน 90° (หักเฟรมสองข้างของราง)  
  ป้าย “เส้น 6 ม.” แต่คำนวณที่ 5,800 มม.  
  **แก้:** ให้เลือกมุมตัด แล้วใช้สูตรให้ตรงแบบ · ป้ายความยาวเส้นให้ตรงของจริง

- [ ] **ท่อทองแดงแอร์บอกให้ขยับไซซ์แต่ผลไม่ขยับ**  
  `hvac.ts` → `calcPipe`  
  tip บอกเดินไกลเกิน 15 ม. ให้เลื่อนขึ้นหนึ่งไซซ์ แต่ผลลัพธ์ยังเป็นไซซ์เดิม  
  **แก้:** ถ้า `run > 15` ขยับขั้นจริง หรือขึ้นสถานะว่ายังไม่ได้ขยับ + ยึดคู่มือรุ่น

- [ ] **สายไฟแอร์คนละตารางกับช่างไฟ**  
  `hvac.ts` → `breakerForBtu` เป็น heuristic ตาม BTU  
  `electrical.ts` → `calcCable` เป็น วสท. 5-20 + Kt/Kg  
  **แก้:** ให้หน้าแอร์เรียกสูตรสายไฟชุดเดียว หรือติดป้ายชัดว่าไม่ใช่ตาราง วสท.

### 🟡 Medium — ควรปรับให้ตรงหลักการและไม่หลอกผู้ใช้

- [ ] **จัดสตริงโซลาร์** — ตัวคูณ Voc เย็นตรึง ×1.15 ไม่มีอุณหภูมิแผง / βVoc; ช่อง `vmax` ใช้ทั้งพิกัดเครื่องและเพดาน MPPT  
  ไทยอากาศไม่ถึง 0 °C ค่า 1.15 เผื่อเกิน (อนุรักษ์นิยม) แต่ถ้าเกินพิกัดต้องสถานะไม่ผ่านแบบเด่น

- [ ] **แรงดันตก** — คิดแค่ R ไม่รวม X (รับได้ถึง ~95 ตร.มม. ตามที่เขียน) · ช่องขนาดสายกรอกอิสระไม่ผูกตารางที่ขาย · ไม่เตือนเมื่อสายใหญ่/ระยะยาว

- [ ] **คืนทุนโซลาร์** — `derate = 0.8` และ 2.3 ตร.ม./แผง เป็นเลขลอย · ราคาตั้งต้น 45,000 บาท สำหรับระบบที่สูตรเองบอก ~9 แผง (~4 kWp) ต่ำเกินจริง คืนทุนออกมาสั้นเกินงานบ้านไทย (มัก 5–8 ปี)

- [ ] **ระยะโก่งคาน** — สมการช่วงเดียวโหลดกระจายทิศถูก แต่ช่างไม่มีค่า I (ซม.⁴) ในมือ · ใช้ `g = 9.81` ไม่ดึง `UNIT.gravity`

- [ ] **แรงลม + ความหนากระจก** — คำนวณ `q = 0.6v²` แล้วไม่ได้นำ q ไปใช้ กระโดดตาราง 6/8/10/12 มม. ไม่ใช่ มยผ. 1311 / ASTM E1300 · headline ดูเหมือนสเปกออกแบบ

- [ ] **แปลงพื้นที่/ปริมาตร** — หน่วยตร.ม. กับลิตรอยู่ใน dropdown เดียวกัน; หน่วยไม่เข้าตารางจะ `?? 1` เงียบ (1 ลบ.ม. กลายเป็น 1 ตร.ม. ได้)

- [ ] **คณิตศาสตร์รูปทรง** — วงกลมใช้ ก = เส้นผ่านศูนย์กลาง แต่กระบอก/กรวยใช้ ก = รัศมี ทั้งที่ช่องเดียวกันเขียนว่า “ก / กว้าง / รัศมี”

- [ ] **พีทาโกรัสโหมดหาด้านฉาก** — ด้านทแยงสั้นกว่าอีกด้านได้ผล 0 แบบเงียบ

- [ ] **หน้า “คิดทั้งงาน” ส่วนใหญ่เรียก `result()` ไม่มี explain**  
  plumbing / tile / paint / roof / steel / ceiling / vinyl / glass / handyman / general  
  เครื่องมือย่อยมีสูตรครบ แต่หน้าชุดงานที่เป็นทางเข้าหลักกลับเป็นกล่องดำ

- [ ] **เผื่อเสียซ่อนในสูตร** (ขัดหลักการข้อ 4.6)  
  ลามิเนต ×1.1, กระเบื้องบิ้วอิน ×1.1, หลังคา ×1.1, ฝ้ายิปซัม ×1.1 — ผู้ใช้ปรับไม่ได้

- [ ] **Magic number นอกทะเบียน** (ขัดกฎเหล็กของ `constants.ts`)  
  น้ำยาแอร์ ก./ม. (20/30/40), derate โซลาร์ 0.8, พื้นที่แผง 2.3, ประสิทธิภาพปั๊ม 0.55, Head สำรอง 1.2, ประตู-หน้าต่าง 1.8/1.2 ตร.ม., ความหนาแน่นกระจก 2.5 (มี `MATERIAL.glassDensity` แล้วไม่ใช้), E เหล็ก 200000, α 12e-6

- [ ] **สัดส่วนผสมคอนกรีต** — แบ่งปริมาตร 1:2:4 ตรง ๆ ไม่คิดช่องว่างมวลรวม · น้ำ = ถุง×25 หลังปัดขึ้น ทำให้ w/c เพี้ยน

- [ ] **คิดทั้งงานประปา** — ไม่ใช้จำนวนคนไปคิด Q · Head = ชั้น×3.2+8 โดยไม่ใช้ระยะท่อที่กรอก · Q ล็อก 30–35 ล./นาที

- [ ] **กระเบื้องบิ้วอิน** (`calcHandymanTile`) ยาแนวคิดหยาบ พื้นที่ × 0.4 กก./ตร.ม. สูงกว่าสูตร ISO ของหมวดกระเบื้องหลายเท่า

### 🟢 Low — เก็บตก

- [ ] หม้อแปลง LED เกินตาราง 300 W แล้วปัดเป็นขั้น 50 W แบบเงียบ

- [ ] ยาแนว: ข้อความแทนค่าเขียนหน่วยผิดเป็น “ม./ตร.มม.” (ตัวเลขสูตรถูก)

- [ ] เทสแคตตาล็อกใช้เกณฑ์ `toBeGreaterThanOrEqual(15)` ทั้งที่มี 85 ตัวคำนวณ และไม่จับ `∞` / ค่าติดลบ / ค่าว่าง

## ส่วนที่ 2 — UX / UI ที่ต้องแก้

ไม่ได้ไล่คลิกครบทุกจอในรอบนี้ ประเมินจากโค้ดหน้า `/assistant`, `AssistantHome`, `Fields`, `CalcScreen`, `ResultPanel`, `FormulaNote`, `TradeView`

### สิ่งที่ทำได้ดีอยู่แล้ว

### 🔴 / 🟠 ใช้ผิดได้ถ้าไม่แก้

- [ ] **Validation เป็นข้อความใกล้ช่อง** ไม่ใช่แค่ HTML `min/max`

- [ ] **ช่องที่ไม่เกี่ยวกับโหมดยังโชว์ทั้งชุด**

- [ ] **ความชันหลังคาเป็น %** (ซ้ำกับสูตร) — ต้องมีตัวสลับองศาใน UI ไม่ใช่แค่แก้เอกสาร

- [ ] **หน้า job ไม่มีทางไปเครื่องมือย่อยที่ถูกย่อมา**  
  ได้เลขรวมแล้วถ้าอยากเช็กยาแนวแยก ต้องกลับไปเลือกการ์ดเอง

## ส่วนที่ 3 — สายงานและหัวข้อที่ควรเพิ่ม

เลือกจากงานที่ช่างไทยทำบ่อย และของที่ร้านขายได้จริง ไม่ใช่เพิ่มเพื่อให้ครบตำรา

### ข้อค้นพบสำคัญเรื่องร้านค้า

Assistant กับร้าน **ไม่เชื่อมกันเลย** — ไม่มีลิงก์ `/shop` `/cart` ใน `src/components/chang` หรือ `src/lib/chang`

สำคัญกว่านั้น: **ร้านไม่ได้ขายวัสดุก่อสร้าง** ตรวจ catalog ~161 SKU แล้วเป็น Tool Holder / Battery Mount / Box Organizer / เจลล้างมือ / Blower Nozzle / Wall Mount — ปูน 0 · กระเบื้อง 0 · พุก 0 · ซิลิโคน 0 · ใบตัด 0

ห้ามทำ “คิดปูนกาว 12 ถุง → ใส่ตะกร้าเจลล้างมือ” จะทำลายความน่าเชื่อถือของสูตร

**เชื่อมได้ 4 ชั้น:**
1. บล็อก “ช่างสายนี้ใช้อะไรกัน” ใต้ผลลัพธ์ — map `tradeId` → หมวดสินค้าจริง (ที่เก็บแบต, ที่เก็บดอก, เจลล้างมือ) ไม่ map วัสดุ
2. ถามค่ายแบตครั้งเดียว จำใน localStorage — 78/161 SKU ผูกแพลตฟอร์ม M18/M12/18V/20V
3. ใช้ 72 เครื่องมือเป็น demand signal ว่าควรผลิต/สต็อกอะไร (คลิปรับระดับ, ชุดพุก, ใบเพชร)
4. ใบเสนอราคาขอเบอร์/อีเมล → lead ช่างมืออาชีพ

| **งานผนังเบา / โครงคร่าว** — โครง C/U, แผ่นยิปซัมผนัง, ฉนวน, สกรู/ม. | คนต่อเติมบ้านใช้บ่อย ตอนนี้มีแต่ฝ้า | S |

### P1 — มีแล้วแต่ควรแตกหัวข้อย่อย

| สายงาน | หัวข้อที่ขาด |
|---|---|
| ไฟฟ้า | ตารางขนาดท่อร้อยสาย, โหลดวงจรรวม (หลอด/พัดลม/เต้ารับ), เครื่องตัดไฟรั่ว (RCD/RCBO), สายฝังดิน/XLPE (ตอนนี้เตือนว่าต้องเปิดตารางอื่นแล้วแต่ยังไม่มี) |
| แอร์ | ขาแขวน/น็อต, สายน้ำทิ้งคอยล์เย็น, ระยะสูงต่างคอยล์ร้อน-เย็น |
| หลังคา | ตะเข้ราง (valley) + แผ่นกันซึม — ตอนนี้บอกว่าไม่รวม แต่ไม่มีเครื่องมือ |
| ก่อฉาบ | เสาเอ็นแนวตั้งทุก 3–4 ม. (tip มี เครื่องมือยังไม่มี) |
| ประปา | สุขภัณฑ์ห้องน้ำ — ระยะกับดัก (trap), จำนวนข้อต่อตามแบบห้อง, ขนาดท่อโถ |
| กระจก-อลูฯ | มุ้งลวด, ซีลยาง, ลูกล้อ, door closer, ช่องเผื่อวงกบ+PU foam |
| บิ้วอิน | cutting list แผ่น 4×8, ระยะสกรูขอบ, sag ชั้นวาง |

### P2 — ไว้รอบหลังเมื่อชั้น C นิ่งแล้ว

- งานโซลาร์แยกสายจากช่างไฟ เมื่อเครื่องมือโซลาร์เกิน 5 ตัว (ตอนนี้อยู่รวมกัน หาไม่เจอ)
- งานกล้อง / เน็ตเวิร์ก / CCTV — ขนาด HDD, PoE, ความยาว UTP — สูตรชั้น A/B ทำง่าย และตรงกลุ่มลูกค้ากระเป๋าคาดเอว
- งานระบายอากาศ — CFM/ACH ห้องน้ำ-ครัว ต่อจากแอร์ที่มีอยู่
- งานรั้ว / เหล็กดัด — ระยะเสา, น้ำหนักแผง, ปริมาณสีกันสนิม
- งานสวน / ภูมิทัศน์ — DIY มูลค่าต่อคลิกต่ำกว่า ลำดับหลัง
- งานดับเพลิง / ถนนลาดยาง — **ไม่ทำ** (ต้องมีวิศวกร / ไม่ใช่กลุ่มลูกค้า)

### อย่าเพิ่งทำ

PPE / lockout-tagout / นั่งร้าน — สำคัญแต่ถ้าทำไม่ครบมาตรฐาน จะอันตรายกว่าไม่มี  
งานคอนกรีตเทเสา-คานรับน้ำหนัก — มีสัดส่วนผสมแล้วและจัดชั้น C ถูกทิศ อย่าขยายเป็น “แบบโครงสร้าง”

### จัดหมวดเมื่อสายงานเยอะขึ้น

โครง 4 เสาตอนนี้ยังพอ แต่ `general` เป็นเสาที่มีสายเดียว จะไม่ scale  
เมื่อเพิ่มกันซึม + ผนังเบา + ประมาณราคา + เครื่องมือช่าง ให้:

1. เพิ่ม `keywords` ใน `ToolDef` (บีทียู, กาวยาแนว, ไฟตก, ทับหลัง) — ของชิ้นเดียวที่ทำให้หาเจอมากที่สุดต่อบรรทัดโค้ด
2. แกน “วันนี้จะทำอะไร” เป็นทางเข้าหลัก: สั่งของ · เสนอราคา · เลือกสเปก · เช็กหน้างาน · เปิดตาราง
3. ยกแถบใช้ล่าสุด/ปักหมุดขึ้นเหนือตัวแปลงหน่วย และจำค่าที่กรอกล่าสุดของแต่ละเครื่องมือ (ตอนนี้รีเซ็ตทุกครั้ง)
4. มือถือ: การ์ดเครื่องมือเป็นลิสต์แน่น เก็บรูปไว้ที่ระดับสายงาน — เห็น 8–10 ตัวต่อจอแทน 1.5
5. เพิ่ม content type `reference` ให้ตารางใน `constants.ts` มีบ้านของตัวเอง
6. ห้ามเกิน 2 คลิกจากหน้าแรกถึงเครื่องมือใด ๆ

## ลิสต์รวมเรียงลำดับลงมือ (ยังไม่แก้ในรีวิวนี้)

### รอบ 1 — ปิดของที่ทำให้เลขผิดหรืออันตราย

1. ตาราง P–T น้ำยาแอร์ + golden test (ค่าตั้งต้น SH/SC วินิจฉัยผิดอยู่แล้ว)
2. ช่องว่าง/ศูนย์/ติดลบ ห้ามตอบ `∞` หรือถุงติดลบ
3. สายไฟเกินตารางต้องไม่ตอบแบบผ่าน
4. ท่อ PVC เลือกจาก ID
5. สูตรเหล็กทับหลัง (คูณ 8)
6. ลวดเชื่อมแยกชนิดแนว
7. BTU ห้ามนับแดด/ชั้นบนซ้ำ
8. พุกยิปซัมต้องดูน้ำหนัก

### รอบ 2 — คำเตือนและความโปร่งใส

9. `DISCLAIMER_C` ติดคัดลอก / แชร์ / PNG และอยู่เหนือคำตอบ
10. หน้า job แอร์/ก่อฉาบ รวม disclaimer ชั้น C
11. ยกระดับทุกหน้า “คิดทั้งงาน” ให้มีสูตร+ชั้นความเสี่ยง
12. บันไดเทียบกฎกระทรวง
13. เทสต้องจับ `∞` / ติดลบ / P–T ไม่ใช่แค่ “ค่าตั้งต้นไม่มี NaN”

### รอบ 3 — UX หน้างาน

14. Conditional fields ตามโหมด
15. ความชันหลังคาสลับ % / องศา
16. คำไทยติดคำเทคนิค
17. เปิดช่องเผื่อเสียที่ยังซ่อน + ย้าย magic number เข้า `constants.ts`
18. `keywords` + ทางเข้า “วันนี้จะทำอะไร” + จำค่าที่กรอกล่าสุด

### รอบ 4 — ขยายคุณค่าธุรกิจ (อย่าขยายบนสูตรที่ยังผิด)

19. หน้าตารางมาตรฐานจาก `constants.ts`
20. ประมาณราคา + ใบเสนอราคาส่งไลน์
21. สายงานเครื่องมือช่าง & แบต + จำค่ายแบต
22. บล็อก “ช่างสายนี้ใช้อะไรกัน” ใต้ผล — **ห้ามใส่ตะกร้าวัสดุที่ร้านไม่มีขาย**
23. กันซึม / ผนังเบา เมื่อของเดิมชั้น C นิ่งแล้ว
