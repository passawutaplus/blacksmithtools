## รายการที่ควรแก้ (เรียงตามความสำคัญ)

### 1) [สูง] สูตรลวดเชื่อมยังไม่แยกตามชนิดแนวจริง

- ตำแหน่ง: `src/lib/chang/tools/steel.ts` (`calcWeld`)
- ประเด็น: `fillet / v / sq` ใช้ `volFactor` โครงเดียวกัน ทำให้ผลต่างระหว่างชนิดแนวไม่สะท้อนหน้าตัดจริง
- ผลกระทบ: ค่าลวดเชื่อมอาจคลาดในการใช้งานจริง โดยเฉพาะงานที่ต้องควบคุมของและต้นทุน
- ข้อเสนอแนะ: แยกสูตรหน้าตัดตามชนิดแนวเชื่อมให้ชัด พร้อมเพิ่ม golden test ต่อชนิดแนว

### 2) [สูง] เครื่องมือความเสี่ยงโครงสร้างบางตัวยังเป็น heuristic

- ตำแหน่งหลัก: `src/lib/chang/tools/glass.ts` (`calcWind`), `src/lib/chang/tools/handyman.ts` (`calcScrew`)
- ประเด็น: ใช้เกณฑ์ขั้นบันไดประมาณการ เหมาะ pre-check แต่ยังไม่เทียบเท่า code-based calculation
- ผลกระทบ: ผู้ใช้อาจเข้าใจว่าเป็นค่ามาตรฐานออกแบบจริง
- ข้อเสนอแนะ: เพิ่มโหมด “มาตรฐาน” (code-based) หรือเพิ่มคำเตือน/ขอบเขตการใช้งานให้ชัดกว่าเดิม

### 3) [สูง] กรณีอินพุตไม่สมเหตุผลบางเครื่องมือยังตอบแบบเงียบ

- ตำแหน่ง: `src/lib/chang/tools/general.ts` (`calcTriangle` โหมด `leg`)
- ประเด็น: เคส A <= B ให้ผลลัพธ์ 0 โดยไม่มี error state
- ผลกระทบ: ผู้ใช้ไม่รู้ว่ากรอกผิด อาจนำเลขผิดไปใช้ต่อ
- ข้อเสนอแนะ: ใส่ validation + ข้อความ error ที่อธิบายวิธีกรอกที่ถูกต้อง

### 4) [สูง] อ้างอิงสูตรยังไม่ครบระดับ audit-ready

- ตำแหน่ง: `explain.refs` หลายเครื่องมือ
- ประเด็น: บางรายการเป็นข้อความอ้างอิงกว้าง ๆ ไม่มี edition/year/url
- ผลกระทบ: ตรวจย้อนและทวนมาตรฐานลำบาก
- ข้อเสนอแนะ: บังคับ schema อ้างอิงให้ครบ (มาตรฐาน, ตาราง/ข้อ, ปี, ลิงก์)

### 5) [กลาง] หน้า “คิดทั้งงาน” หลายตัวไม่กางสูตรเท่าเครื่องมือย่อย

- ตำแหน่ง: หลาย `job` ยังใช้ `result()` แทน `resultX()`
- ประเด็น: ผู้ใช้เห็นผลรวมแต่ trace ที่มาของเลขไม่ครบ
- ผลกระทบ: ขัดกับจุดขาย “กางสูตรดูได้ทุกบรรทัด”
- ข้อเสนอแนะ: ย้ายหน้า job สำคัญให้รองรับ `explain` ครบเหมือนหน้า tool

### 6) [กลาง] ฟอร์มบางจุดยังแสดงช่องไม่เกี่ยวกับโหมดที่เลือก

- ตัวอย่าง: โหมดกรอกแอมป์แต่ยังเห็นช่องวัตต์พร้อมกัน
- ผลกระทบ: ผู้ใช้ใหม่สับสน เพิ่มโอกาสกรอกซ้ำ/กรอกผิด
- ข้อเสนอแนะ: conditional fields ตาม mode เพื่อลด cognitive load

### 7) [กลาง] Search ยังพึ่งชื่อและ blurb เป็นหลัก

- ตำแหน่ง: `src/lib/chang/catalog.ts` (`searchCatalog`)
- ประเด็น: ยังไม่รองรับ synonym เชิงหน้างานอย่างเพียงพอ
- ผลกระทบ: หาเครื่องมือยากเมื่อผู้ใช้พิมพ์ศัพท์ช่างจริง
- ข้อเสนอแนะ: เพิ่ม keyword map/synonym dictionary ต่อเครื่องมือ

### 8) [กลาง] ยังไม่มีช่วงค่าความเชื่อมั่น (confidence range)

- ประเด็น: สูตรจากแนวปฏิบัติ (T5) แสดงค่าเดียว
- ผลกระทบ: ผู้ใช้อาจตีความว่าเป็นค่าตายตัวเชิงวิศวกรรม
- ข้อเสนอแนะ: แสดงค่า low-mid-high หรือช่วงแนะนำในผลลัพธ์

## ข้อเสนอแนะ UX/UI

### สิ่งที่ควรเพิ่มเพื่อใช้งานง่ายขึ้น

- เพิ่มแถบสรุปความเสี่ยง `A/B/C` ชัด ๆ เหนือผลลัพธ์ พร้อม action ถัดไป
- เพิ่มสลับโหมดผลลัพธ์: `สรุปสั่งของ` / `อธิบายสูตร`
- เพิ่ม compare mode (เทียบ 2 ทางเลือกในเครื่องมือเดียว)
- เพิ่ม pre-check checklist ก่อนสั่งของต่อเครื่องมือ
- เพิ่มบันทึกโปรเจกต์หน้างาน (ชื่อลูกค้า/พื้นที่/วันที่)

### สิ่งที่ควรช่วยลดการหลงทาง

- เพิ่มทางเข้าแบบ “เริ่มจากงานอะไร” (task-first)
- เพิ่ม decision helper สั้น ๆ สำหรับผู้ใช้ที่ไม่แน่ใจว่าจะเลือกเครื่องมือไหน

## หัวข้อสายงานที่ควรเพิ่ม

- งานกันซึม/ดาดฟ้า (membrane, primer, slope-to-drain)
- งานคอนกรีตเทโครงสร้างเบื้องต้น (ปริมาตรเท, รถโม่, slump คร่าว)
- งานผนังเบา/กั้นห้อง (โครง, แผ่น, ฉนวน, สกรู)
- งานประตู-หน้าต่าง/วงกบ (clearance, shim, PU foam, sealant)
- งานสุขภัณฑ์ห้องน้ำ (fall, trap, ท่อ, fitting)
- งาน PM เชิงป้องกัน (แผนตรวจรอบอุปกรณ์)
