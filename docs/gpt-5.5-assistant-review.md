## รายการที่ควรแก้

### P0 ต้องแก้ก่อนใช้จริง

#### 1. งานไฟฟ้า fallback เป็นค่าสูงสุดแบบเงียบ

- ตำแหน่ง: `src/lib/chang/tools/electrical.ts` (`calcCable`, `pickBreaker`, `pickCable`)
- ประเด็น: ถ้าโหลดเกินขนาดเบรกเกอร์หรือตารางสายสูงสุด ระบบ fallback เป็นค่าสูงสุดและตอบเหมือนปกติ
- ผลกระทบ: ผู้ใช้อาจเข้าใจว่าสาย/เบรกเกอร์ที่แนะนำเพียงพอ ทั้งที่อาจเกินช่วงออกแบบ
- ข้อเสนอแนะ: ถ้าเกินช่วงตาราง ให้แสดงข้อความชัดเจนว่า "เกินช่วงตาราง ต้องให้วิศวกรออกแบบ" และไม่ควรคืนผลลัพธ์เหมือนคำนวณสำเร็จ

#### 2. งานแอร์คิดทั้งงานมีผลไฟฟ้า แต่คำเตือนไม่ครอบคลุม

- ตำแหน่ง: `src/lib/chang/tools/hvac.ts` (`hvacJob`, `breakerForBtu`)
- ประเด็น: หน้า "คิดทั้งงานแอร์" แสดงเบรกเกอร์และสายไฟ แต่ `explain/risk` ยังอิงสูตร BTU เป็นหลัก
- ผลกระทบ: งานที่โยงกับไฟฟ้าควรมีคำเตือนระดับสูงกว่า เพราะเกี่ยวกับ safety และมาตรฐานติดตั้ง
- ข้อเสนอแนะ: เพิ่ม disclaimer/คำเตือนชั้น C สำหรับส่วนไฟฟ้า และระบุว่าต้องตรวจคู่มือรุ่นจริงหรือให้ช่างไฟ/วิศวกรยืนยัน

#### 3. งานก่อฉาบคิดทั้งงานทำคำเตือนโครงสร้างตกหล่น

- ตำแหน่ง: `src/lib/chang/tools/masonry.ts` (`masonryJob`, `calcLintel`)
- ประเด็น: หน้า "คิดทั้งงานก่อฉาบผนัง" รวม `calcLintel()` ซึ่งเป็นงานโครงสร้าง แต่ส่งกลับคำอธิบายจากสูตรอิฐเป็นหลัก
- ผลกระทบ: ผู้ใช้อาจไม่เห็นคำเตือนเรื่องทับหลัง/โครงสร้าง
- ข้อเสนอแนะ: รวม `risk/explain` ของ `calcLintel()` เข้าไปในผลรวม หรือแยก section คำเตือนโครงสร้างให้ชัด

## P1 ควรแก้เพื่อความถูกต้องและ UX

### 1. หน้า "คิดทั้งงาน" หลายหน้าไม่กางสูตรครบ

- ตำแหน่ง: หลาย job เช่น `plumbingJob`, `tileJob`, `paintJob`, `roofJob`, `steelJob`, `ceilingJob`, `vinylJob`, `glassJob`, `handymanJob`
- ประเด็น: ใช้ `result()` โดยไม่มี `explain`, `risk`, `chart`
- ผลกระทบ: ผู้ใช้เห็นผลรวม แต่ตรวจที่มาของเลขไม่ได้ ทั้งที่หน้าเดี่ยวมีสูตรครบกว่า
- ข้อเสนอแนะ: ยกระดับหน้า "คิดทั้งงาน" ให้แสดงสูตร/สมมติฐาน/คำเตือนครบเหมือนเครื่องมือเดี่ยว

### 2. Validation ยังพึ่ง browser มากเกินไป

- ตำแหน่ง: `src/components/chang/Fields.tsx` และสูตรที่ clamp/fallback ค่า
- ประเด็น: input ใช้ `min/max` ของ browser แต่สูตรยังคำนวณต่อด้วย `Math.max(...)`, clamp หรือค่า default
- ผลกระทบ: ผู้ใช้กรอกค่าผิดช่วง แต่อาจได้คำตอบเหมือนถูก
- ข้อเสนอแนะ: เพิ่ม error message ใกล้ field และไม่คำนวณเมื่อค่าหลุดช่วงหรือไม่สมเหตุผล

### 3. หน่วยพื้นที่/ปริมาตรอยู่ใน dropdown เดียวกัน

- ตำแหน่ง: `src/lib/chang/tools/general.ts` (`calcAreaVol`)
- ประเด็น: เลือกหน่วยพื้นที่และปริมาตรปนกันได้ เช่น งานพื้นที่แต่เลือก "ลิตร/คิว"
- ผลกระทบ: มีโอกาส fallback เป็นตัวคูณผิดแบบเงียบ
- ข้อเสนอแนะ: แยก unit group ตามชนิดงาน หรือ validate ว่าหน่วยตรงกับประเภทการคำนวณ

### 4. ค่าคงที่แรงโน้มถ่วงไม่สอดคล้องกัน

- ตำแหน่ง: `src/lib/chang/tools/general.ts` (`calcWeightForce`, `calcForce`)
- ประเด็น: ใช้ `9.81` แทน `UNIT.gravity = 9.80665`
- ผลกระทบ: ขัดหลักการใช้ตัวคูณหน่วยตามนิยามเดียวกัน
- ข้อเสนอแนะ: ใช้ค่ากลางจาก `UNIT.gravity` ทั้งหมด

### 5. สามเหลี่ยมมุมฉาก clamp เคสที่เป็นไปไม่ได้

- ตำแหน่ง: `src/lib/chang/tools/general.ts` (`calcTriangle`)
- ประเด็น: โหมดหาด้านฉากใช้ `Math.max(..., 0)` เมื่อกรอกด้านทแยงสั้นกว่าอีกด้าน
- ผลกระทบ: ระบบตอบค่า 0 แทนที่จะบอกว่าข้อมูลผิด
- ข้อเสนอแนะ: เพิ่ม validation ว่าด้านทแยงต้องยาวกว่าด้านประกอบ และแจ้ง error ชัดเจน

### 6. สูตรที่ขึ้นกับเงื่อนไขหน้างานควรรับข้อมูลเพิ่ม

- ตำแหน่ง: `calcWind`, `calcStair`, `calcString`
- ประเด็น: เงื่อนไขจริงบางอย่างยังไม่ได้ให้ผู้ใช้กรอก เช่น ประเภทอาคาร/พื้นที่ลม, กฎหมายบันได, temperature coefficient, อุณหภูมิต่ำสุดของแผง
- ผลกระทบ: คำตอบอาจเป็นค่าประมาณที่ผู้ใช้ตีความว่าเป็นมาตรฐานออกแบบ
- ข้อเสนอแนะ: เพิ่ม input เงื่อนไขสำคัญ หรือแสดงว่าเป็น pre-check เท่านั้น

## P2 เพิ่มคุณภาพและความง่ายในการใช้งาน

### 1. ลด UI ที่ดูเป็น AI/ตกแต่งเกินไป

- ตำแหน่ง: `src/components/chang/FormulaNote.tsx`
- ประเด็น: ใช้ emoji ในหัวข้อย่อย เช่น `📌`, `🧭`, `⚠️`, `📚`
- ข้อเสนอแนะ: เปลี่ยนเป็นหัวข้อไทยเรียบ ๆ เช่น "สรุป", "วิธีคิด", "ข้อควรระวัง", "อ้างอิง"

### 2. ลดคำ technical/อังกฤษที่ผู้ใช้หน้างานอาจไม่เข้าใจ

- ตัวอย่างคำ: `Flow + Head`, `self-level`, `Best Fit`, `PF`, `EER`, `MPPT`, `SH/SC`
- ข้อเสนอแนะ: เพิ่มคำไทยสั้น ๆ หรือ helper text ข้าง field/result เช่น "แรงดันตก", "ประสิทธิภาพแอร์", "จุดทำงานแผงโซลาร์"

### 3. Search combobox ควรเสริม accessibility

- ตำแหน่ง: `src/app/assistant/AssistantHome.tsx`
- ประเด็น: มี role พื้นฐานแล้ว แต่ยังควรเพิ่ม `aria-activedescendant` และ id ของ option ให้ keyboard/screen reader เข้าใจสถานะเลือก
- ข้อเสนอแนะ: ทำให้ search ใช้งานด้วย keyboard ได้ครบขึ้น

### 4. Test ควรตรวจครบมากขึ้น

- ประเด็น: ตอนนี้ test ผ่านดี แต่ยังบังคับ `explain` แบบขั้นต่ำ
- ข้อเสนอแนะ: ค่อย ๆ เพิ่ม test ให้ทุกเครื่องมือและทุกหน้า "คิดทั้งงาน" ต้องมีสูตร, สมมติฐาน, risk และ reference ตามระดับความเสี่ยง
